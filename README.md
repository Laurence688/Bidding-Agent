# Laura · Bidding Agent 投标助手

运行在本机的投标工作台，支持产品问答、单条 SOC、Excel 批量应答、标书拆解与翻译、知识库构建、人工审核和原表副本导出。

便携版面向 Windows 10/11（64 位），已内置 Python 3.11.17、Node.js 24.18.0、后端依赖和已构建网页，无需单独安装 Python、Node 或 npm，也不修改系统 PATH。首次使用仍需联网下载 Embedding 模型，模型服务账号和业务知识库由使用者自行配置。

## 双击启动（推荐）

1. 在 GitHub Release 下载 **Laura-Portable-Windows-x64.zip**，解压完整目录。GitHub 的 Code → Download ZIP 是源码包，不含运行环境。
2. 双击 `Laura.exe`。首次会自动打开初始化窗口，使用内置环境检查依赖并下载 Embedding 模型；请保持网络连通，完成后自动打开网页，并创建桌面图标。初始化失败可检查网络后再次双击重试。
3. 日常双击桌面 Laura 图标或项目中的 `Laura.exe`。启动器自动启动 API/Worker，并用系统默认浏览器打开普通网页，保留浏览器地址栏和标签页。
4. 关闭最后一个 Laura 标签页后约 8–10 秒停止本机服务。刷新、页面内跳转、切换到其他标签页不会停止；打开多个 Laura 页面时需全部关闭。重复双击只复用同一套服务，并重新打开网页。

退出时未完成的任务会中断，之后可在界面显式恢复；不会删除资料、索引、配置或历史。浏览器崩溃、计算机睡眠或长时间断开本机连接也可能使会话结束，需要重新双击启动。

`Laura.exe` 依赖整个项目目录，不能单独移动；桌面请使用快捷方式。快捷方式丢失时运行 `scripts/CreateDesktopShortcut.ps1` 重建。启动失败会给出提示，日志位于本机 `data/logs/desktop-launcher.log`。

## 源码安装与手动常驻服务

仅源码包需要先安装 Python 3.11（64 位）和 Node.js 22.12+。便携包已经内置这些环境，可直接双击启动；也可运行以下脚本，脚本会优先使用内置环境。

1. 下载仓库 ZIP 并解压，或克隆仓库。在项目根目录打开 PowerShell。
2. 执行安装（仅当前 PowerShell 进程放开脚本策略）：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Setup.ps1 -DownloadEmbedding
.\Start.ps1
.\Status.ps1
```

`Setup.ps1` 创建项目独立的 `.venv`，安装后端和前端依赖，构建界面，并从配置模板生成本机配置。`-DownloadEmbedding` 显式从 Hugging Face 下载公开的 `Qwen/Qwen3-Embedding-0.6B` 到 `data/local-models/embedding`，不使用仓库作者的模型文件或凭据。使用前核对模型仓库的许可与访问条件。网络不可达时可先执行不带此参数的安装，再从有权访问的渠道获得完整模型目录并放到同一位置。

Python 的 `py -3.11` 启动器不可用时，指定可执行文件：

```powershell
.\Setup.ps1 -Python 'C:\Python311\python.exe' -DownloadEmbedding
```

打开启动器输出的网址（默认 `http://127.0.0.1:8765`，端口占用时可能变化）。此处 `Start.ps1` 是手动常驻服务模式，停止使用 `.\Stop.ps1`，关闭网页不会自动停止；需要随页面关闭停止时，请使用 `Laura.exe`。已有旧版服务时先正常停止，再使用图标启动器。

## 首次配置

1. 系统设置 → 生成 API：填写你自己的 API 地址、模型 ID 和密钥，保存并选择供应商。内网API 排在首位；从[公司申请页面](https://maas-openclaw.zte.com.cn/zte-paas-coclaw-ui/#/getkey)取得 URL、模型 ID 和 Key 后分别粘贴。其他公开供应商保留地址和模型预设。
2. 系统设置 → 运行权限：内网API 首次点击“保存并启用内网API”并确认联网；以后保存即可。其他接口通过运行权限内网API 首次点击“保存并启用内网API”并确认联网；以后保存即可。其他接口通过运行权限内网API 首次点击“保存并启用内网API”并确认联网；以后保存即可。其他接口通过运行权限内网API 首次点击“保存并启用内网API”并确认联网；以后保存即可。其他接口通过运行权限内网API 首次点击“保存并启用内网API”并确认联网；以后保存即可。其他接口通过运行权限明确允许生成 API 联网，再执行连接检查。生成需要调用你选择的服务，费用由你的账号承担。
3. 确认 Embedding 模型目录可用。完整目录至少包含 `model.safetensors`、`config.json`、`tokenizer.json`、`modules.json`、`1_Pooling/config.json`。
4. 登记自己的产品型号，创建项目和知识库。上传有权使用的 DOCX、XLSX 或可提取文字的 PDF；预览切分后执行构建、发布，并将知识库绑定到项目。扫描 PDF 需先进行 OCR。
5. 在工作中心进行问答、单条 SOC 或 Excel 应答。Excel 先核对工作表、行列映射与输入范围，再确认提交；到审核工作台复核证据与应答。

## 应答与导出

FC 表示完全符合，PC 表示部分符合，NC 表示不符合，UNKNOWN 表示证据不足或尚未确定。UNKNOWN 不等于 NC，并会阻止正式导出。正式 Excel 回填要求条目通过人工审核、证据与版本校验；导出生成原表副本。问答和翻译不自动构成正式合规结论。

## 数据与配置

产品清单、知识库、历史任务与评测集初始为空。项目运行后自行生成 `data/`，包含本机数据库、上传资料、索引、运行日志与结果。密钥保存在服务端 `.env.local`；生成 API 地址、模型 ID 等本机配置由 `config/*.example.yaml` 初始化，后续修改写入忽略的 YAML 文件。

本地 Embedding 不发送资料到向量服务。生成所需文本和证据发送给你选择的模型接口。LangSmith 默认关闭，启用后会发送追踪内容，需自行配置。请按业务资料的授权范围使用。

`.gitignore` 排除数据、密钥、本机可写配置、日志、依赖、模型权重、截图与录屏。提交自己的修改前仍应检查暂存文件；已被 Git 跟踪的文件不会因为新增忽略规则自动停止跟踪。

## 常见问题

- 启动提示未构建前端：重新执行 `.\Setup.ps1`，或 `npm --prefix frontend run build`。
- 依赖或模型下载失败：检查网络、Python/Node 版本和磁盘空间，修复后重试；安装器遇到失败会中止。
- Embedding 文件不完整：下载完整模型目录；不要只放单个权重文件。也可在系统设置登记自己的本地 Embedding 配置。
- 无可用知识库：登记产品并完成构建、发布及项目绑定；源码不提供作者的产品知识库。
- 无法生成：核对已保存的供应商、地址、模型 ID、密钥、联网权限与账号额度。
- 中断的任务：重新启动后在界面显式恢复；已发送的模型请求可能计费。
- 日志位置：`data/logs/`，仅留在本机。

便携版和源码版都不能把软件启动或测试通过等同于真实模型准确率、业务验收或任意工作簿保真。请先用自己的资料验证，再用于正式投标。

## 自动更新与数据保留

在系统设置 → 检查更新中明确检查，程序自动下载新版并校验；安装并重启前自动备份原目录的数据和配置。有排队或运行任务时暂不安装，失败会尝试恢复。也可关闭 Laura 后双击 `检查更新Laura.cmd`。

0.3.x 用户首次下载本版完整包，运行其中的检查更新脚本并选择原来的 Laura 文件夹，自动升级原目录。知识库、对话、记忆、模型设置留在原目录，不要求手动备份或重新配置。以后从原目录页面或脚本更新即可。不要直接换用空的新目录。
