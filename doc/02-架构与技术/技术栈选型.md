# SOC 投标助手技术栈与配置

出版版本：v0.4.2

本文说明当前组件、配置和取舍，依赖可安装不等于任意机器兼容或业务质量已经验收。

## 1. 已采用的技术

| 层次 | 当前采用 | 采用原因与代价 |
|---|---|---|
| 运行时 | 独立 Python 3.11 环境 | 后端声明 `>=3.11,<3.12`；便携发行内置 Python 3.11.17，不修改系统解释器 |
| API / 数据契约 | FastAPI、Pydantic | 请求、结构化输出和状态契约显式；合法 JSON 不等于业务正确 |
| 编排 | LangGraph 固定图、SQLite checkpointer | 显式节点和分支适合审计；恢复还依赖自有任务表和节点提交缓存 |
| LLM 组件 | langchain-core 消息与格式转换 | 只复用必要组件；供应商请求实际使用 HTTPX 自有适配器 |
| 数据 | SQLite `app.db` / `checkpoints.db`、本地文件 | 面向单机单用户，减少运维；任务和条款串行，不能视为高并发服务 |
| 检索 | Sentence Transformers、Qwen3-Embedding-0.6B、FAISS、SQLite FTS5 | 本地语义与词法双路；产品/知识快照分区，RRF 与规则优先级融合 |
| 解析 | python-docx、openpyxl、pypdf、pdfplumber | 结构化读取 Office/PDF；固定 PDF 页码单独生成并保留，不以字符数推算 |
| 正式 Excel 回填 | Python 标准库 ZIP/XML 定点修改 | 只改确认的目标，保持其余包部件；openpyxl 用于读取和核查，不承担任意文件无损保存 |
| 前端 | React 19、TypeScript、Vite | 中文会话、长表审核、参数对照、日志及配置；增加独立构建成本 |
| 验证 | pytest、Vitest、Playwright + Chrome | 规则、接口与交互分别验证；合成模型浏览器测试不证明业务准确率 |
| 观测 | 本地调用、节点、事件、审核和标注记录 | LangSmith 0.14.12 已声明显式依赖，默认关闭；独立 SDK 发送器与本地持久队列，页面/下载保持诊断白名单 |

没有采用 DeepAgents、ADK、自主主/子 Agent、外部向量数据库或独立 reranker。是否替换需由具体缺陷与同集对照决定，不以框架数量衡量能力。

依赖依据：后端声明、后端精确锁、前端声明、前端精确锁。锁文件是项目复现依据，不代表这些版本在所有机器上兼容。

## 2. 模型与分节点策略

仓库默认值来自 models.yaml 和 processing.yaml。本机环境文件/环境变量可以覆盖 URL 和模型 ID；密钥仅在本机服务端处理。实际运行以该 Run 保存的有效配置为准。

| 项目 | 当前仓库默认 |
|---|---|
| 配置版本 | 以模型设置页和每个 Run 的配置快照为准；切换及保存会递增 |
| 主用生成 | `deepseek-flash`，`https://api.deepseek.com` |
| 豆包手动备选 | `doubao-seed-2-1-pro-260915`，`https://ark.cn-beijing.volces.com/api/v3` |
| GLM 手动备选 | `glm-4.7-flash`，`https://open.bigmodel.cn/api/paas/v4`；JSON 模式、关闭思考，180 秒单次超时 |
| 内网API | 独立 OpenAI Chat Completions 兼容配置，Base URL、模型 ID、API Key 待实际填写 |
| 接口 | Chat Completions，非流式，`json_object` 请求 + Pydantic 校验 |
| DeepSeek 单次超时 / 输出上限 | 90 秒 / 4096 Token |
| DeepSeek 请求上下文控制值 | 32000；网关以字符估算 + 输出预算检查，不是供应商容量实测 |
| 翻译、拆 Claim | DeepSeek `structured_thinking=disabled` |
| Claim 判断、语义核验 | `thinking_mode=auto`，输出上限 4096；包含最终英文的语义核验 |
| 英文生成 | DeepSeek `thinking_mode=disabled`，输出上限 4096 |

`auto` 当前表示不向适配器显式发送 enabled/disabled，由供应商默认行为决定；它不等于已证明没有思考。思考控制仅按供应商支持范围发送：DeepSeek 和智谱标准 API 有各自适配，不能把字段直接当作豆包或内网API 等价设置。

当前生成接口以设置页的明确选择与任务快照为准；公共 API 与内网API由用户选择，失败不自动切换。备选接口的真实手动切换和当前分节点策略的业务效果仍待验证。这里只描述配置，不承诺当前延迟或判断质量。

来源：配置装配、模型策略和预算、请求适配。

## 3. 调用预算、错误与用量

持久预算键为 `run_id + clause_id + claim_id + logical_node_name`。当前四档案 API 运行每键最多两次总尝试，始终使用所选供应商；不会自动调用备选。历史未采用档案选择的主备快照保留原来“主两次、备一次”的解释与兼容代码，不代表新任务仍这样发送。成功调用同样消耗次数；补检索或恢复不重置该键。一次条款有多个模型节点，不是整条只调用两次。最终英文核验使用独立 Claim 占位 `__output__`。

仅暂态网络、超时、429/5xx 在余额内退避；鉴权、配置、JSON/Schema、截断或语义失败不会通过无限重试修复。HTTPX transport 无额外自动重试。`invocation_id`、`invocation_attempt`、`call_kind` 区分新一轮判断与同次请求重试；旧日志推定分类需显示不确定。

NC 使用固定英文且跳过口径生成；此前的翻译、拆分和反证判断仍可能调用模型。UNKNOWN 不生成正式支持口径。用量以供应商返回为准：已知小计、缺失次数、推理 Token、缓存命中分开显示，推理/缓存不能重复加到总量。详情见 运行观测与评测。

## 4. 本地检索与证据预算

| 配置 | 当前值 | 解释 |
|---|---|---|
| Embedding | Qwen3-Embedding-0.6B；CPU | 日常服务显式 CPU；历史离线 CUDA 构建不是当前服务使用 GPU 的证明 |
| 编码窗口 / batch | 1024 Token / 4 | 长记录分窗口后均值聚合及归一化；证据记录保持完整 |
| `retrieval_top_k` / `rrf_k` | 8 / 60 | 首轮每路最多24后取8；补检索每路最多48后取16 |
| `candidate_limit` | 8 / Claim | SOC 最终用于判断的候选预算，独立于检索器返回数量 |
| `evidence_max_characters` | 12000 / Claim | 引用正文总字符预算，不是 Token 数；不截断单条证据 |

初次与补检索都经过预算收敛；补检索优先新增候选，无新增选中证据不追加判断。参数场景在候选池内优先 Feature List。具体排序、准入、查询扩展及 QA 差异统一见 [RAG 设计](RAG设计.md)，不在此另维护算法副本。

索引文件保存 Embedding 指纹；模型/归一化/查询指令/窗口关键配置变化不能沿用不匹配索引。当前没有独立 reranker 或相似度阈值，参数值和引用有效性也不能由向量相似度代替。

## 5. 部署、数据与安全边界

API 与 Worker 为两个独立进程；启动入口 Start.ps1，默认本机 `127.0.0.1:8765`。单并发 Worker 不受页面切换/连接断开取消；停止和恢复规则见架构文档。业务库、知识原件、索引、模型文件、环境与 `.cache` 不在 Git 中，备份需要单独覆盖。

Prompt 与共享证据规范独立保存；UI 支持整包修订、版本冲突和草稿，保存不调用模型。配置快照保留有效 Prompt/模型/检索/processing/知识版本；这不冻结 Python 实现、Schema 或所有渲染规则。评测 processing 已按快照恢复，并记录代码/依赖指纹；历史执行环境仍未自动封存。

生成模型当前仍走云 API；“本地日志和本地检索”不等于资料从不离开本机，准入后的证据会随模型请求发送给所选供应商。日志和公开诊断采用不同访问边界，不得将底层原始响应直接展示或公开。

旧本地生成快照仅保留兼容读取，不提供新的本地生成入口。页面只保留 API 发送权限和四档案选择，不再提供本地生成路径、模式或启停。Embedding 仍在本地，指纹与索引不因生成接口切换改变。旧本地任务若需再执行，应新建 API 运行。

## 6. 替代方案的启用条件

| 候选变化 | 触发证据 | 必须同时比较 |
|---|---|---|
| 增加 reranker | 金标准证据已进入候选但持续排在预算之外 | Recall@候选、最终引用正确性、延迟、资源 |
| 其他生成 API | 当前所选 API 的质量、延迟或可用性存在已测不足 | 同输入完整链路质量、错误肯定、耗时、失败率与用量；用户手动选择 |
| 多条并发 / 外部队列 | 单并发有可量化吞吐需求 | 检查点隔离、SQLite 锁、调用预算、顺序与成本 |
| 更换向量模型或分块策略 | 人工召回集显示系统性漏召回 | 同一语料/问题集、索引重建、版本回查和整体耗时 |

以上是后续决策条件，不是本次实施事项，也不构成已经获得更高性能的结论。

外部 SDK 的资源接口和弃用策略需持续跟进，升级前验证项目、字段与同步兼容。SDK 维护状态不能代替真实云端可用性验证。

## 7. 页面与独立文档任务增量（软件已实现）

以下是当前界面与独立文档任务的选型和边界。用户原运行配置保留。

| 能力 | 选型与边界 |
|---|---|
| 界面组件 | 保留 React／TypeScript／Vite，已引入并锁定 Ant Design 6.6.8、icons 6.3.4 及中文语言包，不迁移到 Ant Design Pro 或其他框架 |
| 主页演示 | SVG 连线＋CSS 动画；合成示例、暂停／重播／静态降级，资源本地提供，不调用模型或引入视频渲染服务 |
| 独立拆解／翻译 | 复用 FastAPI、Worker、模型网关及文档解析；独立任务输入、工作流、分段结果和产物服务，与 SOC 类型和门禁隔离 |
| 中文报告与双语文件 | 复用 python-docx／openpyxl 生成独立 DOCX／XLSX；原文定位保留，不承诺原版式保真，也不改写原件 |
| 项目审核记忆 | 继续 SQLite 及现有管理服务，仅查询、来源有效性和启停；不引入 Mem0、LangMem 或记忆向量库 |
| 上下文摘要 | 独立版本化摘要与消息清单，仍走所选 API 和调用限制；不是长期事实记忆，也不压缩 SOC 或文档原文 |

新流程的模型、提示词、分段与语言需固定并可回查；各自质量用人工样本验收，不能因为复用解析库或 API 就视为具备完整标书理解和翻译能力。模型及 Embedding 路线仍以 V2 为准。
