# 上下文管理

出版版本：v0.4.6

上下文由当前任务数据和冻结的会话历史组成。业务事实按本次原文、产品及知识快照核验。会话历史用于理解指代、术语和讨论进度。

## 从会话到模型请求

1. 入队时固定项目、会话、选定产品及已完成消息。运行记录保存消息清单、内容快照和摘要身份。指向某条批任务结果的显式引用只带选中的条目。
2. 节点按白名单取原文、表格上下文、证据与历史，构造该阶段的请求。已准备的节点请求可在同一输入下复用。
3. 发送前估算消息、Schema 和输出预留的窗口占用。达到约 80%、历史多于四对且保护内容可以装入窗口时，可以摘要较早历史。保留最近四对完整问答、显式引用以及本次输入与证据。
4. 原始历史仍可回查。摘要失败时使用仍能装入窗口的原历史。最终超过硬上限时以 `CONTEXT_LIMIT` 阻断该请求。

历史结论只是上下文，例如「再解释上一条」可以复用上一条的指代。产品是否符合仍要按当前有效资料核验。项目经验另见 [记忆管理](05-记忆管理.md)。
