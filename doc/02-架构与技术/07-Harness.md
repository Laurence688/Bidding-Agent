# Harness

出版版本：v0.4.6

Laura 的 Harness 是模型周围的执行与交付机制。LangGraph 执行条款状态图并写图检查点，Laura 实现任务队列、证据准入、结果聚合、失败恢复、权限和正式交付规则。

## 一条条款的执行契约

| 层次 | 负责的工作 |
| --- | --- |
| 任务入口 | 固定原表或原文、产品、Prompt、模型与知识版本，建立作业和条款绑定 |
| 节点与模型 | 用固定节点拆要求、找证据和核验结论，模型网关负责 Schema 与调用预算 |
| 业务结果 | 按子项证据聚合 FC、PC、NC、UNKNOWN，明确未决原因，保存结果与引用 |
| 审核与导出 | 人工核对并批准当前结果，服务端检查完整范围、有效来源、原表和审核版本 |

业务逻辑需要分别确认原文覆盖、引用定位和语义支持。例如原表缺少要求阈值时，产品手册给出的能力值不足以判断是否符合。此时保留 UNKNOWN，待补齐原始要求再创建新运行。正式 Excel 回填会阻断仍未解决的 UNKNOWN。

## 中断与恢复

SQLite 的 `app.db` 保存作业、运行、条款结果、节点提交、尝试及审核记录，LangGraph 另外用 `checkpoints.db` 保存图状态。Worker 启动时将已经失去进程的运行作业标为中断。用户显式恢复后，同一运行重新排队，直接复用已提交条款，未提交条款按运行、条款、节点和输入指纹复用已保存的节点输出。

条款结果、绑定与最终节点提交在同一个业务事务中落库。未提交的节点可能重做，已记录尝试继续计入预算。若进程在外部请求发出后退出，本地状态无法确认远端已执行或计费几次。

## 权限与交付

本地服务绑定回环地址，校验请求来源、主机及本机会话令牌，文件按受控路径访问。外部模型调用需满足任务快照及当前联网授权，并命中相应用途的服务端点。生成凭证由后端从本机环境配置读取，任务快照只需保存供应商配置及凭证变量名。正式 Excel 回填由人工批准和服务端校验共同决定。
