# SOC 投标助手当前计划与验收顺序

出版版本：v0.4.0

本计划维护当前产品路线、交付条件与后续验收顺序；具体需求见 [PRD](PRD.md)，系统执行与持久化见 [架构设计](../02-架构与技术/架构设计.md)。路线中的目标不表示业务质量、性能或兼容性已经验收。软件可启动、合成流程完成和真实资料验证分别记录，不互相替代。

## 1. 当前阶段与路线

当前产品具备项目与会话、结构化知识、单条和 Excel SOC、人工审核、运行观测、提示词管理、范围修订及参数约束；独立标书拆解和翻译使用各自任务契约。生成使用用户所选 API，本地向量化和索引负责检索，不自动跨供应商切换。用户准备自己的产品与资料，公开发行不预装业务知识库和历史结果。

后续路线按“输入与可比性 → 完整固定样本 → 同输入全链路质量 → 交付与目标机”推进。优先保护原始要求、有效证据、必要条件、四态含义与审核门禁；不通过放宽 UNKNOWN 或删减事实换取表面速度。当前实现不等于对任意资料、工作簿、供应商或电脑作出质量承诺。

## 2. 评测与可比性要求

| 主题 | 交付要求 | 核对条件 |
|---|---|---|
| 处理预算冻结 | 评测使用入队时的候选数、字符预算和节点策略 | 排队后改变全局设置，不改变该实验的固定输入与策略 |
| 完整输入 | 样本保留 Excel 要求值、原表上下文和必要生命周期条件 | 金标准只交给评分器，不进入执行输入；缺字段明确标记 |
| 机器与人工结果 | 运行报告沿结果版本追溯机器初始值，人工修改独立记录 | 继承与缺失基线使用一致规则，不把同一结果重复计数 |
| 可复现边界 | 保存代码、Schema、提示词渲染器和依赖身份 | 配置哈希相同不等于封存历史执行环境，报告必须指出实现变化 |
| 质量判据 | 先定义必要要求、证据资格和可接受输出 | 人工标注分歧可回查，不以 FC 占比或 UNKNOWN 下降代替正确性 |

业务样本、真实供应商调用及固定范围的完整实验须另行审定。观测与评测提供核对机制，不能自动生成“达到业务门槛”的结论。

## 3. 再建立完整输入的固定样本集

从原始 Excel 和已确认应答范围形成测试输入，保留 Value、单位、比较方向、原坐标、标题/邻列上下文。独立导出的“原文 + 旧 UNKNOWN”文件不能替代完整参数输入。人工排除意见需要可复核，不能将全部短文本当标题自动删除。

首批样本至少覆盖以下互相独立的失败边界；样本数量由覆盖需求决定，不把一次小样本通过视为整批通过：

- 数值要求与资料实际值：覆盖 K/M、共享资源和缺阈值反例。
- 功能支持与参数豁免：覆盖明确数值阈值不能误豁免的反例。
- 标准/等级：覆盖只有 Internet-Draft 的情况。
- 条件/OR：真实替代关系、AND 组合、数量等价说明及条件遗漏。
- 证据资格：具体机框/系列混用、生命周期、真实供货/许可证承诺、确实无证据。

样本 gold 包含结论、必要 Claim、关键条件、证据定位和可接受英文；保存标注分歧，不用 FC 占比替代正确性。

## 4. 完整链路对照，再运行固定范围

固定输入、工作流/Prompt、模型策略、知识快照和软件版本。比较 Claim 遗漏、错误肯定、四态混淆、引用有效性、参数值/条件、英文完整性，再比较整条历时、Token、追加判断收益及失败返工。

当前默认采用 DeepSeek API，本地生成路线已退出。重排、并发或进一步压缩思考仍需在同输入质量对照后决定。不能删条件、接受无证据 FC 或绕过审核来制造提速。

## 5. 交付检查与持续维护

软件验证分别覆盖后端规则、前端状态、浏览器交互、真实资料和供应商调用。记录适用版本、输入范围、排除项、失败与限制；只对实际完成的层次作结论。备用接口的真实手动切换、原生 Excel 展示、完整人工金标准和业务门槛应独立验收。

便携包内置 Python、Node.js、固定后端依赖与已构建网页；首次向量模型准备仍需联网。目标电脑需核对解压路径、运行时加载、默认浏览器、启动/停止、存储权限和更新恢复，不能把开发电脑上的成功视为任意电脑兼容。保留配置、知识库、历史结果和用户密钥，更新不得静默覆盖用户数据。

当前文档按单主题维护：PRD 管需求，架构管执行，RAG 管证据检索，观测管指标，技术栈管配置，本页管后续工作。使用指南说明可执行操作，公开版本只包含当前说明和必要质量边界，不分发私人执行档案。

## 6. 页面与能力升级实施顺序

目标：把工作中心分为产品问答与应标、标书拆解、标书翻译；统一 Ant Design 界面，分离审核与日志，补齐上下文及知识管理，最后以真实能力和合成动画完善主页。完整交互以 [界面与交互设计](../03-界面与交互/界面与交互设计.md) 为准，新业务边界见 [PRD](PRD.md)，类型／快照／恢复约束见 [架构设计](../02-架构与技术/架构设计.md)。

架构继续使用 React／Vite、FastAPI、独立 Worker、固定工作流、SQLite 与本地 RAG；新增流程共用底层能力但不复用 SOC 判定与导出规则。V2 的所选 API、同供应商两次总尝试、不自动切换和本地 Embedding 约束继续有效。以下 P0—P5 是能力交付分组，与 V2 交付计划的同名阶段各自独立。

| 批次 | 可交付结果 | 依赖与验收 |
|---|---|---|
| P0 文档基线 | 整合方案、PRD、架构、技术栈、目录与离线阅读副本 | 使用指南、产品契约和架构说明一致；不以文档完整代替业务验收 |
| P1 界面与工作区 | Ant Design、导航、轻量回复、审核表格抽屉、运行日志、观测折叠及设置 | 保留草稿、原运行、版本校验与正式导出门禁 |
| P2 文档任务与翻译 | 独立类型与上传、分段结果／恢复、单条／多文件翻译、DOCX／XLSX 产物 | 接入任务按类型分发；错误、取消及部分完成不伪装成功 |
| P3 标书拆解 | 整份标书中文分类提取、原文定位、覆盖检查与报告 | 复用 P2 基础；区别未发现与未处理，冲突并列，不自动判断废标 |
| P4 上下文与数据管理 | 消息清单冻结、自动／手动摘要、知识库回收站、型号同步及记忆展示 | 摘要失败保留原文，硬窗口阻断；历史来源和项目隔离不变 |
| P5 主页及整体验收 | Laura／你的投标助手、三条真实亮点、连续应标动画、新模块入口 | P2／P3 通过验收后再展示可用入口；离线展示、暂停与静态降级 |

### 6.1 能力交付清单

- 界面与工作区：统一中文控件、导航、输入框、表格、抽屉和折叠表单；保留未保存草稿与历史链接，正确区分当前和历史运行。
- 审核与日志：服务器按当前结果筛选和分页，来源仅引用最终证据，任务详情固定运行版本；聊天展示不代替审核资格。
- 文档任务：使用独立输入、输出、上传用途和 Worker 分发，不能全局放宽问答或 SOC 的型号与证据约束。
- 分段恢复：冻结文件、段落位置、语言、术语、模型与提示词；结果和完成标记原子保存，取消、重试与部分完成均可解释。
- 翻译交付：单条文本可复制，多文件输出双语 DOCX/XLSX 或 ZIP；原件不覆盖，数字、单位、否定、术语与条件需人工核对。
- 标书拆解：分类提取项目、资格、时间、技术、商务交付、评分及重点关注信息；逐项保留原文引用和覆盖状态，不自动判断废标。
- 上下文与数据管理：入队冻结消息清单与摘要版本，最近完整问答及当前约束保留；摘要失败保留原文，超硬窗口明确阻断。
- 知识库与项目：预览、构建、发布、绑定分别确认；回收和恢复遵守版本与任务保护，历史引用、原件和共享产品保留。
- 演示与可访问性：首页合成示例提供暂停、重播和减少动画的静态降级；示例不是业务结果或速度承诺。
- 独立业务验收：用人工审定样本核对拆解、翻译与 SOC；同输入质量对照通过后再评价成本、耗时和目标机可用性。

### 6.2 重点验收与证据边界

重点覆盖旧任务和历史结果跳转、大批量后端筛选、UNKNOWN 门禁、同名不同版本引用、构建中回收知识库、跨型号消息摘要、并发压缩与硬窗口、长段数字／单位／否定、跨文件冲突、处理范围不完整、部分产物及服务重启。

只复用已提交节点／段落；在途未落库调用仍可能再次发送并计费。新文档任务只计通用运行与用量，不进入 SOC 四态、审核及正式回填统计。主页不承诺文档内容绝不出域、自动复用、全离线生成或未经验证的节省比例。

界面与模拟测试、真实模型调用、业务质量和干净电脑安装分开验收；评测集与目标机验收各自记录适用版本和结论。

## 7. 专项归并与下一步

导航与共享对话、输入区、业务命名、模型与审核布局、知识库创建及切分作为同一产品维护，页面规则见 [界面与交互设计](../03-界面与交互/界面与交互设计.md)，知识切分与版本规则见 [RAG 设计](../02-架构与技术/RAG设计.md)。不并列维护互相矛盾的旧实施方案。

优先完成完整输入的人工固定集和同口径业务评测，核对真实供应商、明确开启的外部观测同步、目标机安装与恢复边界。真实建库能执行只说明构建链可运行，尚不能宣布检索质量提高。界面风格调整不替代业务改进；新知识版本仍须使用者确认发布，整理文档不触发建库、发布或模型请求。
