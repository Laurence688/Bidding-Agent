# SOC 投标助手产品需求文档

出版版本：v0.4.0

本文说明当前用户流程、产品契约与尚未完成的能力；工程验证不能代替真实业务质量验收。

## 1. 产品目标与范围

为本机个人用户提供产品资料问答、技术 SOC 应答、Excel 批处理、人工复核和原表副本回填。首先保证原始要求完整、结论有适用证据、未决项可解释、正式交付经过审核，再用固定输入和人工判据衡量质量与成本。

| 项目 | 当前约定 |
| --- | --- |
| 用户与部署 | 本机个人使用；保留本地用户与项目隔离，不提供登录、多人权限或公网服务 |
| 产品 | 产品目录初始为空，使用者登记自己的型号；QA/SOC 每个任务绑定一个明确型号，具体子型号不自动等同系列型号 |
| 输入 | 产品问答、单条文本 SOC、普通 `.xlsx` 技术条目；评测使用独立入口 |
| 输出 | 中文界面和辅助理解；正式 SOC 英文口径、四态结果及可定位来源 |
| 执行方式 | 持久后台任务和固定 SOC 工作流；RAG 是共享能力，评测是执行器，不引入自主多 Agent 调度 |
| 模型 | 当前使用明确选择的 API，豆包、GLM、内网API 为手动选项；新运行冻结所选配置，不自动跨供应商重试；向量模型保留本地 |
| 人工职责 | 确定范围、补充必要输入、核对证据与条件、评价结果、批准正式交付 |
| 正式回填 | 检查当前任务完整应答范围，不以页面筛选、已加载分页或本次新处理条数代替范围 |

当前 SOC 应答入口不包含 Word/PDF 标书。第 10 节新增的独立拆解/翻译支持 DOCX、文字型 PDF 和 XLSX，但不将其变成 SOC 自动应答入口。扫描件 OCR、商务报价生成、法务/财务判断、完整 BOM 或项目供货校验、自动提交投标、自动判断废标、多人审核仍不纳入本次。提炼原文明确的商务、付款及资格条件不等于作出法律或财务判断。

本文定义产品行为；[架构设计](../02-架构与技术/架构设计.md)定义执行与持久化契约，[RAG设计](../02-架构与技术/RAG设计.md)定义知识及证据规则，[运行观测与评测](../05-质量与验收/运行观测与评测.md)定义指标与诊断，[技术栈选型](../02-架构与技术/技术栈选型.md)说明依赖与取舍。[README](../README.md)提供导航，[计划书](计划书.md)安排后续工作，记录未关闭问题。

## 2. 用户闭环

1. 创建项目、选择默认产品和会话；提交前确认本次任务型号及模式。
2. 单条输入保留完整原文；Excel 上传后先预检并本地识别工作表、表头、原文和 Value 要求值，自动生成摘要及最多五条样例，确认后开始处理。新上传结果固定写入原表副本右侧新增三列。
3. 启动后台任务；查看进度、四态、来源、参数对照、节点原因及用量。处理完成不等于批准。
4. 逐条核对原文、拆分、引用与条件；分析标注记录对错/缺口，审核批注记录处理依据，批准决定正式交付资格，三者分开。
5. 标题或非应答内容被误纳入时，先标注“不需应答”，生成可核对的范围方案，再启动新版本。输入事实或原表变化建立新输入；中断任务恢复原执行。
6. 对当前完整范围的有效结果逐条批准。通过门禁后生成原表副本；独立审阅报告或诊断 JSON 用于分析，不是正式回填。

当前 UI 为统一对话工作台：同一输入框由用户手动选择“问答／应标”。问答＋文字执行 PRODUCT_QA；应标＋无附件文字执行 SOC_SINGLE；应标＋普通 Excel 执行持久预检确认卡，再确认后创建 SOC_BATCH。不会根据自由文本自动切模式。问答模式添加 Excel 时保留附件但禁止发送，明确提示切换应标。附件旁文字只作为任务备注，排除于原始条款、SOC 输入快照和后续问答历史。

结果与真实进度保留在对话，消息及详情绑定当时 run_id；旧运行只读，重跑另发新记录。产品问答展示完整回答与来源；单条展示四态、原因、英文与引用；批量展示进度及审核入口。确认前不调用应答模型。消息默认最近一页，可加载更早记录。项目创建入口位于项目选择菜单，全局返回按钮取消，详情提供自己的返回入口。

草稿、型号、模式、待发送附件按项目和会话保留于本次浏览器打开期间；已发送卡片与最新映射入库，刷新可恢复。本次不提供待发送文件跨浏览器刷新持久化。实现入口

## 3. 技术条目、章节上下文与输入范围

### 3.1 技术条目与标题

#### 上传确认流程

正常流程为“选择附件 → 发送 → 上传及预检 → 对话内确认范围和列 → 开始应标”。确认卡关联会话、型号、备注、最新映射及确认后的任务和运行；修改配置立即撤销旧映射，重新校验后才能提交。确认使用版本及归属检查、整卡一次任务约束，同一确认卡重试或不同请求键重复确认仍只返回同一个任务。摘要显示工作表、原文列、要求值列、纳入条数、跳过行数和新增结果列位置；样例最多五条，存在要求值时至少展示一条参数项。删除原来的“预览映射”按钮、覆盖确认框及最终确认复选框，不默认铺开整表、目标坐标和覆盖全文。

“调整识别”按需展开工作表、表头行、原文列和要求值列；识别使用本地表头及样本规则，不调用模型，唯一可靠候选才自动选中，有歧义时要求明确选择，不再默认原文为 A 列。真实无表头文件提示先补表头，不将第一条要求当作表头静默丢弃。

“调整范围”提供行范围与分页勾选。只自动跳过空行和合并续行，其他非空行默认保留；标题不会自动删除，历史人工排除仅提示、不自动应用。用户排除项保存原文、坐标和 `upload_selection` 来源，随输入快照及重跑传播，并保留必要的最近前置上下文，不伪造审核标注。

新流程固定采用 `output_mode=append`，由后端在已有内容、实体格式和合并范围右侧分配三列；延伸到 XFD 的整段尾随默认列格式不作为已占用内容，原格式定义仍保留。表头固定为“SOC 结论”“SOC 英文应答”“SOC 引用”。表头与结果位置一起冻结到输入快照，导出使用既有 OOXML 定点回填及保真检查。旧任务继续使用原映射地址，不补写新表头，不改写历史结果。

任何文件、列和范围变更立即使旧预览失效，刷新成功前禁用开始按钮；忽略迟到请求并防止重复入队。识别或映射错误就地显示。具体实现和验证状态以和为准。

技术条目是需要应答的产品能力、指标、标准、条件或项目义务。章节标题、纯说明和提示语不应统计成能力条目，但系统不自动保证识别所有标题；新上传默认纳入非空原文，由用户按需调整范围，空白行及合并单元格续行按映射规则跳过，原表保留。

标题可以是理解后续条款的上下文。例如 “IP当前版本” 下的 “Maximum routes” 不能脱离章节理解。范围修订从已排除内容中取同工作表、前方最近一条作为 `preceding_context`，连同同行非输出单元格与要求值保存。当前不是完整章节树解析器，也不自动组合任意多级标题；复杂层级、跨行条件仍须人工核对。

原表内容仅是“招标要求与上下文”，不是产品能力证据。旧 Compliance、Bidding Equipment Specifications、References、应答、备注等列，以及已映射的输出列均排除在模型输入之外；人工标注和批注也不作为判断提示。普通上传、范围修订及旧批任务新执行使用同一原表输入构建器。输入实现

### 3.2 Value、清单和参数输入

- 通过表头识别 Value / Required Value / Requirement Value / 要求值等列，并非硬编码 D 列。允许明确选择要求值列；未指定时自动识别，空列表表示确认没有要求值列。保留单元格、原始值、从原文识别的单位和比较方向；摘要样例供用户核对。
- 上下限分开：原文 minimum / at least 等提示下限，maximum / at most 等提示上限；显式 `>=` / `<=` 优先。无法识别时显示比较方向待核对，不能默认越大越好。
- Value 公式不求值后直接使用；要求值公式拒绝并定位。其他公式不进入模型。缺阈值、单位、配置或比较关系不能用产品值补造。
- 清单逐项保留必要要求，不能因长列表静默裁成三个 Claim。数值等效说明与真正备选方案分别处理；“A 或 B”不能变成同时必须具备 A 和 B。
- 重新上传只有原文/旧结论的摘录表，不会自动恢复原文件 Value、原位置、标题或已排除范围。需回到完整原件或补齐可核对输入。

### 3.3 范围方案与版本动作

范围属于任务的输入快照。项目用于隔离与查找关联历史，不存在把项目全部文件自动合成一份正式交付范围的能力。

| 操作 | 当前行为与边界 |
| --- | --- |
| 生成范围方案 | 仅 Excel 当前运行可用；只排除绑定当前结果、未过期的 `not_requirement` 标注；至少保留一条。保存草稿不调用模型 |
| 启动范围方案 | 核对任务版本、标注摘要、原件哈希及活动作业；创建新运行，沿用历史排除记录，不继承旧结果和批准 |
| 改变方案条件 | 重新生成方案；启动记录实际使用的 `effective_input_snapshot_id`，不改写旧输入 |
| 同文件重新上传 | 按文件哈希、位置和原文提示已有任务的有效“不需应答”标注并链接原任务；不自动排除、继承批准或启动 |
| 恢复已排除条目 | 当前没有直接撤回已启动排除项的 UI/API；需从原文件重新上传、将该行纳入新映射，重新处理和审核 |
| 恢复中断任务 | 只适用于 `interrupted` 作业；沿用原运行/快照与节点提交，不等于新范围或新版本 |
| 重新运行 | 产生新运行，保留旧运行；配置、产品、输入快照和来源均有效且相同时，可继承未变且非 UNKNOWN 的有效结果及审核；输入补齐或配置变化时不继承 |
| 修改 Excel 原文/映射 | 重新上传并确认映射；禁止仅改数据库原文后回填到不同内容的旧原件 |

普通重跑会从原件重新构建批任务上下文；旧输入不完整时创建补齐后的新快照，但无法恢复原文件本来就没有的列。新运行成为当前运行后，旧运行不能继续批准或正式导出；历史分析与标注记录保留。范围服务、任务服务

## 4. SOC 判断与输出契约

### 4.1 固定处理链

输入/型号检查 → 原文与辅助翻译 → Claim 拆分及覆盖检查 → 逐 Claim 检索 → 证据准入 → 逐项判定 → 引用定位及内容校验 → 独立语义核验 → 必要时有界补检索 → 四态聚合 → 英文正文或固定 NC → 程序输出检查及最终语义核验 → 人工审核。

拆分只表达要求，不提前判断支持。必须保留原文位置、数字、单位、否定、条件、AND/OR、等效关系及项目义务。遗漏、跨 AND 合并 OR、缺少备选、翻译歧义或无法覆盖原文时保持 UNKNOWN。输入和检索内容均是不可信材料，不能改变产品范围、系统规则或导出门。

### 4.2 四态与状态分离

| 条款结论 | 必要 Claim 规则 | 正式英文 |
| --- | --- | --- |
| FC | 全部 SUPPORTED，完整性、引用和输出校验均通过 | 基于核验事实生成 |
| PC | 无 UNKNOWN，同时包含 SUPPORTED 和 CONTRADICTED | 明示不满足项及条件 |
| NC | 全部 CONTRADICTED，有明确不满足证据 | 固定文案，不调用英文生成模型 |
| UNKNOWN | 任一必要项未决，或覆盖、适用性、执行、引用、输出校验未通过 | 不保留可交付的确定英文口径 |

缺证据不是 NC，UNKNOWN 不是错误率。能力未知、要求值缺失、项目事实缺失和执行失败用结构化原因区分。PC/NC 为零不证明产品没有不满足项。

任务作业状态包括 `queued/running/interrupted/completed/waiting_review/failed/cancelled`；当前 worker 通常完成后为 `completed`，有型号冲突时可为 `waiting_review`。它们与四态、`pending/approved/revoked` 审核状态分开；作业 `completed` 不授予导出资格。尚未生成结果是“未完成”，不计作 UNKNOWN。状态实现

### 4.3 参数要求与实际支持值

要求值来自原表，实际支持值来自通过准入的产品资料。参数项优先检索同型号、同知识快照的 Feature List，但命中它本身不构成符合性结论。

实际值按 `name / actual_value / unit / conditions / evidence_chunk_id` 保存并绑定引用。程序检查实际值、单位和条件在相应证据中可定位；来源页码、行号、产品名不能充当容量。比较须检查指标含义、型号、配置、版本和共享资源；例如 FIB 共享说明不能改成各路由类型均独立拥有该容量。

| 类型 | 必须保留的判断条件 |
| --- | --- |
| 下限、容量 | 实际值是否达到要求，是否在相同配置和资源口径下成立 |
| 上限、重量、尺寸、时延 | 按原要求方向比较，不套用容量的“越大越好” |
| 单位与 K/M | 保留原资料写法；资料/任务未说明进制时不擅自给出精确换算承诺；米 `m` 与数量级 `M` 不等同 |
| 温度、电压、等级 | 范围端点、工作条件、明确等级均属于事实，不可仅写“支持” |
| 功能支持 | Support/Yes 是布尔标记，不充当实际参数值；普通英文改写不要求逐字出现 Support |
| 监控/限制数量的功能 | 无明确阈值时不强制虚构上限；出现真实阈值后恢复参数约束 |

当前数值候选归一允许部分等效书写和标准编号空格差异，是输出检查手段，不是完整量纲/区间计算引擎。比较方向提取与参数识别有规则边界，最终含义依赖模型语义核验和人工核对。参数遗漏、无法绑定来源、缺真实值不能靠放宽英文检查解决。参数规则、输出契约

### 4.4 产品能力、项目承诺与生命周期

产品资料不能证明本项目已提供许可证、数量、配置或交付承诺。能力询问中的“please provide/state”不必然是供货义务；真正的提交文件、项目承诺和供货条件仍需项目证据，不能凭产品库判 FC。

Roadmap 规划项不证明当前能力。生命周期 EOL/EOS 问题在范围方案中可补充参考日期、具体型号及资料版本，仍须核验版本、时间和型号适用性；缺条件保持 UNKNOWN。这不把具体机框能力自动赋给系列产品，也不是完整生命周期数据库。

## 5. 审核与正式交付

### 5.1 审核工作台

逐条弹窗显示原文、辅助译文、原表上下文、Claim 与判定、英文、参数要求/实际值/条件、来源页码与版本、候选状态、原因及处理日志。来源区区分已核验支持、已核验不满足和候选/未核验；UNKNOWN 可以有已核验子项，不能把全部候选当支持证据。

| 人工动作 | 作用 |
| --- | --- |
| 分析标注 | 正确、错误、待核实、非技术/不需应答；记录期望四态、问题环节及备注，追加历史、绑定结果版本；不改机器结果、不批准、不调用模型 |
| 审核批注 | 记录处理依据或待核对项；不改变结论和批准状态 |
| 修改英文措辞 | 仅 FC/PC 可编辑 `response_en`；保存新版本、撤销批准、排队语义校验；新数字、型号、来源或遗漏参数等先由程序拦截 |
| 批准/撤销 | 批准绑定当前结果版本及来源校验摘要；UNKNOWN 或输出/证据失败不能批准；撤销影响交付资格 |

来源标签由程序按证据生成，正文与来源分别校验，页码不能给正文新能力数字“授权”。措辞语义校验失败转 UNKNOWN 并去掉正式口径；事实、判定、证据或型号变化须新运行。并发编辑检查版本，过期页面不能覆盖新结果。审核实现

### 5.2 正式 Excel 回填门禁

正式导出检查当前运行的完整输入快照：

1. 原工作簿哈希和映射一致，存在 Excel 映射；条款清单非空，无缺失或额外绑定。
2. 全部纳入范围结果已生成、已批准，批准仍绑定同一结果版本和有效来源状态。
3. 无 UNKNOWN、未解决型号冲突、引用/来源/输出错误；证据属于该运行知识快照。
4. 创建、执行和下载时均重验门禁及快照摘要；结果、来源、审核或当前运行变化使旧导出失效。

审核通过的 NC 可导出。筛 FC、只加载首屏、仅重跑部分条目均不等于整批通过；范围修改须先形成新输入快照。当前门禁针对一项任务的完整应答范围，不是项目所有独立任务的自动交付合集。

输出新文件，不覆盖源文件；仅改已确认的结果、口径和引用单元格。OOXML 包定点修改并做保真检查，其他内容/样式/公式/工作表顺序保留。预检采用结构白名单，允许经校验的被动 VML 图片等有限结构；宏、加密、外链、控件或未支持对象拒绝并定位，不承诺任意 Excel 都无损。导出实现、预检

“下载审阅 Excel（含来源）”是新建分析工作簿，含运行概览、逐条结果、人工批注列及引用明细，可保留 UNKNOWN 供复盘；标识非正式投标导出，不回填原件，不授予正式导出资格。审阅报告

## 6. 知识、会话与配置

## 7. 后台执行、成本与诊断

页面切换不取消持久队列；使用图标启动时关闭最后一个 Laura 标签页后，刷新缓冲期结束将停止本地服务。机器或 Worker 停止时不会继续执行。重启识别遗留作业为中断，可恢复；已提交节点按输入指纹复用。在途请求发出后、保存前中断仍可能重复计费，不能承诺外部调用恰好一次。

暂态连接、超时、429/5xx 遵守有限预算；V2 新运行在所选供应商内每逻辑节点最多两次总尝试，不自动跨供应商切换，补检索/恢复不重置预算。旧快照的主两次、备一次规则仅按历史版本解释。结构或校验错误不等于网络错误，不能无限重试。取消阻止后续调度，已完成结果及在途用量保留。

补检索最多一次，先按 `gap_type` 判断是否能通过同产品资料补足。缺要求值、项目事实或明确范围问题不盲目重复检索；当前每轮证据选择至多 8 条、12000 字符，优先真正新增候选，无新增选中候选不追加判断。

观测分别显示机器初始四态、当前结果、人工标注、批准与额外人工介入；Token 包含失败、重试、备用、历史重跑及措辞校验。缺失用量显示已知小计和缺失次数；思考 Token 属于输出，不重复累加。上下文估计与缓存供应商实报值分开，未知不补零。任务墙钟、模型累计、节点时间分别展示，详见[运行观测与评测](../05-质量与验收/运行观测与评测.md)。

## 10. 页面与独立文档能力修订（软件已实现）

### 10.1 导航、对话与审核

采用 Ant Design 统一导航、表单、表格、抽屉、折叠及状态样式。工作中心包含“产品问答与应标、标书拆解、标书翻译”；数据管理包含“知识库、记忆库”；效果评估包含“全链观测、应答审核、运行日志、评测构建”；“工具汇总”改为“效率工具”，下设端口缓存计算。文档中心、系统设置继续独立。Laura 在各层级返回主页，侧栏底部收起/展开不清空草稿。

工作台移除“审核与详情”和完整审核表单。SOC 正文直接置于白底，Sources 按文档及版本稳定编号为 `[1] <文档名>`，仅显示最终引用；不再显示重复的“判定依据”和“查看来源”。问答保持中文自然回答。批量默认显示摘要，展开后分页查看每条结果。NC 仍用固定英文；UNKNOWN 显示未决原因，不补造正式口径。人工修改后的消息标记“已人工修订”，原始结果保留。

执行时实时展示步骤；完成后收起为正文上方用时摘要，展开查看真实步骤、耗时和用量；不展示模型内部推理。应答审核移到效果评估，采用项目级服务器筛选/分页表格和右侧详情抽屉，读取当前有效人工结果；原文、参数、证据和审核记录在抽屉分区，导出门禁统一保留。日志独立成页；全链观测改文案为“Laura处理结果”，各模块独立折叠。所有入口绑定原 `project_id/task_id/run_id/clause_id`，轮询不重置展开状态。

### 10.2 上下文与恢复体验

输入框统一附件、项目、产品、问答/应标/翻译模式、上下文占用和发送控件。上下文是本次模型请求的输入和输出预留，不是会话累计 Token；区分发送前预估（未含待检索证据）、执行后数据、精确/估算/未知及当时模型窗口。SOC 显示节点占用及本次峰值。

问答入队固定已完成、同项目/会话/型号的消息清单，排除当前重复消息、未完成问答及后续消息。达到窗口 80% 且存在较早历史时自动摘要，保留当前输入、最近 4 个完整问答对和当前约束/证据；目标降至 60%，摘要上限为窗口 10% 且不超过 1,024 Token。阈值为软目标，超硬上限明确阻断，不静默删条件。每次摘要最多 3 次模型调用（含重试），摘要请求本身也检查窗口，失败保留原文；原内容仍能放入窗口才继续。摘要关联来源消息并版本化，完整聊天仍保留；提供手动压缩入口，生成期间不并发压缩。

SOC 原文、参数、Claim 与引用，以及新增长文模块的输入，均不通过聊天摘要压缩。工作台保留小型恢复入口，详细诊断到运行日志。恢复复用原运行/快照与已提交结果，重新运行建立新版本；已发出但未落库的调用可能重试，不承诺零重复计费。

### 10.3 标书拆解

新增独立 `TENDER_ANALYSIS` 任务，目的为整份标书及附件的中文要点报告；不强制产品型号，不产生四态、不进入 SOC 审核或正式回填。支持 `.docx`、文字型 PDF、`.xlsx`，Excel 先确认工作表、范围及内容列；同一任务文件视为一套标书及附件，不自动合并项目其他文件。

流程为上传预检 → 保留章节/段落/表格位置的解析 → 分段提取 → 分类汇总去重并列冲突 → 覆盖及定位检查 → 中文报告。固定提炼项目概况、资格与提交材料、时间节点、技术要求、商务与交付、评分条款和重点关注项。每项附中文说明、原文摘录、文件名及页码/段落/单元格。报告采用概览、分类内容和来源抽屉，可复制并下载中文 DOCX。

区分“已处理内容未发现”与“相关内容未处理”；不同文件冲突并列，不自行认定版本优先。只提取原文明示的无效投标条件，不自动判断废标。只覆盖可提取文字，图像内容和未处理区域必须如实标明，不能用摘要掩盖缺失。

### 10.4 标书翻译

新增独立 `TRANSLATION` 任务，支持单条粘贴和 DOCX/文字型 PDF/XLSX 多文件批量；默认英译中，可切中译英，每批明确目标语言。Excel 先确认工作表、范围和翻译列。流程为输入/上传 → 语言与范围确认 → 按段落、表格行或条目分段 → 翻译与术语检查 → 双语对照 → 生成产物。

单条可直接复制；Word/PDF 各生成独立的按段落组织的双语 DOCX，Excel 各生成独立双语 XLSX，多文件可逐个下载或 ZIP 打包。保留原文、译文、来源位置和异常状态，原文件不覆盖，不承诺复刻原版式。术语表按文件固定，产品名、编号、数值、单位、否定和条件须保留；发现异常标记需核对。

两种新任务共用后台、模型配置及通用日志/用量，不自动入产品知识库、项目记忆或应标流程。扫描件、加密 PDF、旧 DOC 及不支持结构在预检明确提示；本次不增加 OCR。冻结文件、分段、语言、术语、模型和提示词版本，逐段保存结果；支持取消、中断恢复、重试失败部分。批次可为“部分完成”，必须显示完成/失败/未处理数量；部分结果下载在文件名及内容标注不完整。修改输入、语言或模型配置建立新运行。

### 10.5 数据管理、设置与主页

知识库采用上传→切分设置→片段预览→向量化→发布，预览不调用向量模型。卡片统一展示型号、文档/片段数、版本和状态，删除进入回收站：停止新任务使用，保留历史证据；构建中先停止构建，已开始运行继续固定快照，恢复后重新确认项目绑定。产品同步已有链路，同页与跨标签页刷新保持目录同步，不能自动改变当前型号和历史绑定。

记忆库继续使用 FastAPI＋SQLite，提供项目已审核历史的搜索、来源、有效性、停用/恢复。手动管理状态与批准撤销、结果替换、来源需复核分别展示；恢复不重新批准。本次仅查阅历史，不增加自动匹配、自动复用或 Mem0/LangMem。

设置改名为文本模型、向量模型、提示词；模型纵向折叠列表保留未保存内容，配置状态与连接/业务验证状态分开。提示词页（含直接链接）提示“建议保留默认提示词。修改可能影响条款拆分、证据判定与最终应答效果，非专业人士请勿修改。”保留默认恢复、版本与冲突控制。文档页滚动超过 400px 出现返回顶部。

主页展示“Laura / 你的投标助手”，用合成 SOC 条目演示要求识别→混合检索→证据核验→四态判定→Response/Sources，最终保留待人工审核标记。三条亮点为“专属知识，数据可控”“单条批量，高效应答”“过程可查，持续改进”；历史仅宣传查阅，文档开放指产品内阅读。模型生成会将必要文本发送给所选 API，不宣称绝对不出域或断网生成。动画可暂停/重播、离开视口暂停、减少动画时显示静态流程；详细文案与动效以[界面与交互设计](../03-界面与交互/界面与交互设计.md)为唯一维护入口。

### 10.6 新增验收边界

除原 SOC 门禁回归外，独立验收长文覆盖、数字/单位/否定与术语、跨文件冲突、原文定位、双语产物、部分完成、取消/重试/恢复以及任务类型统计隔离。新任务不放宽现有 QA/SOC 必填字段和证据规则。主页、界面和模拟测试不等于模型业务质量；新模块通过验收后才作为可用入口上线。真实翻译准确性、拆解完整性和 SOC 质量仍须人工样本验收。
